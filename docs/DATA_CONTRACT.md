# 共用数据合同 v0.1（设计，尚未实现）

此文是接下来基础工作的实现约束，不表示持久化、数据库或真实 AI 已存在。

## 一条梦，多种关联

所有入口共享稳定的 dreamId，不再由各页面复制梦境列表。保留当前数值型示例 ID；后续新记录使用不会随排序变化的唯一 ID，路由比较应统一类型。

Dream：id、dreamDate（用户本地日期）、createdAt/updatedAt、originalText、transcriptText、confirmedText、contentVersion、录音附件引用、示例标志。

- 原始输入保存后不被整理结果覆盖。后续改写保存为新正文版本，而非回填“原文”。
- 迁移当前 raw/body 时分别保留原始与展示字段，不能凭空恢复曾经丢失的内容。
- 先保存记录，再做可跳过的 AI；AI 失败与日志保存失败分开。

Tag：id、type（person/place/theme/event）、name、confirmed。DreamTag 关联梦境和标签。

- 只有用户确认的标签进入统计；显示样式不作为实体身份。
- 一个梦包含同一标签多次仍计一条梦。周期按 dreamDate 计算，明确边界。
- 现有字符串 tags 需要显式迁移；未知类型不自动伪装为已确认的人物或地点。

Asset：id、dreamId、sourceVersion、kind（audio/image）、资源 Blob/地址、status、生成描述及风格。

- image:true 只是旧演示标记，不能迁移成“已有真实图像”。
- 保存重生图像时不静默覆盖旧图；实际 Blob 交给存储层，不塞进页面状态协议。

Session：id、dreamId、sourceVersion、perspective、messages、请求状态。不同梦与视角独立；用户纠正优先，消息不能跨会话混用。

InterpretationCard：id、dreamId/sessionId、sourceVersion、summary、questions、方法说明、生成时间。只有实际生成的卡片才标为真实结果。

PostSnapshot：id、显示名、publicText、publicKeywords、选择的附件副本、createdAt、isDemo；Comment 只关联帖子。

- 私人日志与本机“发布”快照分开；改/删日志不静默改变帖子。
- 预览和帖子渲染只能使用明确公开的字段。关键词模式不能通过详情链接或附件夹带原文、录音或聊天全文。
- 单机梦圈明确标识；目前不设计或假装已完成云端用户权限。

## 读写与失败

页面通过统一读写层列出/取得/保存/删除记录。持久化实现独立于 UI 模板；不更换前端框架。

存储层需要可版本化升级、空库首次示例初始化、备份/导出、错误反馈。不能在升级失败时直接清空用户数据。示例只初始化一次，删除后不因刷新复活。

提交保存前校验；保存过程中禁止重复提交；只有写入成功才显示成功或退出编辑。失败保留草稿。离开有未保存更改时提示。

本地存储只对同一设备、浏览器和 origin 有效；端口或域名变化不自动迁移，部署之前需提供导出/导入策略。

## 下一步验收

1. 从上传版本的新建页保存一条文字梦；刷新后重新打开内容一致。
2. 修改确认稿，不覆盖首次原文；日期和标签不因模板重绘丢失。
3. 删除示例后刷新不复活；导出/备份可读。
4. 存储失败不显示成功，输入不丢失；连续点击不产生重复记录。
5. 原三导航和现有演示入口保持可用；未接通功能继续标演示。
